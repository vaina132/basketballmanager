# Courtside interface direction

This repository builds a basketball management game. The user explicitly requires a game interface throughout, including the overview and future management screens. See [Game design, section 11](docs/game-design.md#11-interface-structure) for the full interface specification.

- Build useful management workspaces around the current club, actual game state, and the next decision. Use compact navigation, readable tables, player information, current condition, and direct actions.
- The overview is the manager's desk: current fixture/result, availability, lineup, concerns, instructions, and relevant activity. Every displayed value must come from implemented game state.
- Do not add landing-page heroes, marketing slogans, promotional feature cards, roadmap banners, oversized decorative artwork, or future-feature advertising to gameplay screens.
- Do not invent fixtures, dates, finances, messages, standings, or club activity to fill a dashboard. Show a simulated date or a Continue action only when the corresponding world/calendar behavior exists.
- Navigation and actions must work. Omit unavailable systems from normal navigation instead of presenting placeholder destinations as playable features. Keep development scope in documentation and use a concise, factual in-game prototype label where necessary.
- On the match screen, retain the large court directly below the score. Keep secondary coaching controls below it; do not restore the standalone shot-clock/possession information panel the user removed.
- Show current stamina with bars and numeric values for active players and reserves. Current match condition is distinct from the permanent stamina attribute. Add text labels for fatigue, injury, and exclusion rather than relying on color alone.
- Keep player identity, displayed lineup, condition, scores, and available actions coherent after substitutions, pause/resume, save/load, and navigation. Presentation must not change simulation outcomes.
- Use the shared charcoal/slate surfaces and amber accent, flat panel borders, compact section bars, and dense readable tables. Keep the navigation and command bar small; gain density through spacing rather than shrinking player names or data below readable body text.
- Team instructions must be directly editable using labeled sliders with visible values, keyboard access, and the same authoritative settings on the overview and match screen. Rotation control is a two-position Manual/Assistant policy. Finished matches disable these controls.
- Preserve keyboard access, visible focus, readable contrast, reduced-motion support, and desktop/tablet usability. Favor useful information density over decorative whitespace.
- Prefer player/staff portraits, meaningful icons, condition/skill bars and direct actions. Keep explanations and detailed accounting behind disclosures; urgent decisions remain visible. Icons retain accessible labels.
- Show career budgets together at the top of management screens, excluding Match, with the labels **Remaining budget**, **Remaining staff budget** and **Player salary budget**. Explain the current staff season and next season's salary budget in tooltips and expanded details. Keep their existing rules and time periods distinct; never add them into a fictional shared spending pool. Detailed accounting must reconcile with the same command guards.
- Scouting must make the next step clear: discover, shortlist, assign an observation, receive a report after the matchday, then review contract options. Keep age and position filters. Shortlisting alone does not request an observation, and unknown data stays unknown.
- Match substitutions support drag, tap/click and keyboard selection of reserves and active players. All routes use the existing authoritative substitution queue and legality rules; pause and settle playback before editing. Career nationality entry supports suggestions and free text; replay codes are optional and are not difficulty settings.

- Match uses score, large court, on-floor/reserve players, coaching, box score and play-by-play in that order. Omit career budgets, the separate named-player substitution picker and the match analysis/settings disclosure. Keep essential substitution, timeout, tactics and pause controls directly usable.
- Show overall ability with knowledge-safe 1-5 stars and match performance on a separate 1.0-10.0 scale. Live ratings use the displayed playback snapshot. PIR and MVP derive from retained match statistics; historical reviews use the original rosters. No appearance means unrated; never invent an MVP for missing statistics or an unplayed default.
- Scouting discovery has age sorting and a staff-quality-dependent visible pool. Wider reach reveals identities, not hidden ability. Reports retain uncertain star ranges; shortlist, queued observations and existing club knowledge remain accessible when reach decreases.
- Keep Club focused on ticket decisions, venue information and actual financial activity. Do not restore expected/cautious forecasts, Dates/payments/assumptions, Accounts/commitments or duplicate Staff/Player wages/Transfers shortcuts in this workspace.

- Assistant advice belongs in the compact Match coaching workspace. Opening it pauses and settles playback; never reveal a later simulation boundary during animation. Hiring and reading advice do not change the manager's choices. Explicit application recomputes from owned squad state and uses normal tactics/substitution commands, with visible coach attribution. Keep existing delegation controls usable without a paid appointment.
